HEADLINE
------------------------------------------------------------------------
Integration point is settled and clean: port the appearance layer into
the server's baseline_adapter.score_candidates_hybrid (the single funnel
every suggestion path already routes through) and thread the two TIFF
paths to its 5 call sites. The model score BLENDS + RE-RANKS inside the
existing geometry gate -- never hard-gates, never auto-confirms.

BUT the ready-made template in the model repo has three latent bugs that
would silently make suggestions WORSE, and the whole thing fails silently
when off. Fix those first. Do not ship the template as-is.

MUST-FIX BUGS IN THE TEMPLATE (ranked -- sharpest finding)
------------------------------------------------------------------------
Two agents independently pulled data/checkpoints/GP04/eval_report.json:
REAL match threshold tau ~= 0.175 (per-session 0.10-0.375), NOT 0.5.
True-match cosine sits ~0.175-0.4. That fact breaks three template
assumptions:

1. score_app fills missing/failed pairs with 0.5 (baseline_adapter.py:230).
   0.5 is HIGHER than a genuine match's cosine. So a candidate whose crop
   failed to extract outranks the real match.
   FIX: fill low (0.0 / below tau), never neutral 0.5.

2. Raw clipped cosine is blended as if it were a [0,1] probability; tau is
   never applied in the blend path (only in unused is_match). Feature score
   lives in [0.4,1.0], cosine centers at 0.175 with negatives clipped to 0
   -- scales don't match, so appearance COMPRESSES the ranking instead of
   sharpening it.
   FIX: calibrate score_app = sigmoid(10*(cos - tau)); 10 = the exact BCE
   logit_scale from training (model.py:188), tau from checkpoint.

3. Train/serve z-shape skew: training pads depth to 5 (_pad_or_crop_z);
   inference never pads. A spine near a z-edge feeds a [3,41,41] tensor at
   serve vs [5,41,41] at train -- no crash (global pooling), silent
   off-distribution embedding.
   FIX: apply the same pad + assert crop shape == cfg.input_shape.

PLUS: tau defaults to 0.5 if the checkpoint key is absent (infer.py:35) --
fail loud instead.

  HTTP microservice = best crash/CUDA isolation but heaviest; reserve as
  escape hatch only if torch can't coexist with the server venv.


OPS HARDENING (backend lens, all real)
------------------------------------------------------------------------
- _cached_matcher global has NO lock -- FastAPI's threadpool lets concurrent
  first-requests each torch.load -> GPU OOM race. Add a double-checked lock.
- _tiff_stats unbounded + unlocked (serves stale stacks, concurrent dict
  race); get_matcher caches by path only (in-place .pt replace serves stale
  model) and stores checkpoint_path unresolved (may reload every call).
  Key caches on path+mtime; resolve on store.
- Biggest latency win: CACHE EMBEDDINGS per (tiff, x, y, z, checkpoint_hash)
  and cosine over pairs, instead of score_coords re-encoding both crops per
  candidate row.


SCIENTIFIC GUARDRAILS (domain lens -- do not skip)
------------------------------------------------------------------------
The model can ONLY ever argue FOR a match (it ranks candidate matches; it
has no "spine is gone" state). NEW/LOST/ARTIFACT are all defined by ABSENCE
of a match. So appearance systematically nudges annotators toward matched
-> inflates stable/persistent_engram, deflates measured turnover -- biasing
the exact headline outcome of a spine-plasticity study.

- Suggest-only, never auto-confirm. Appearance reorders the human's
  candidate list; the human decides. Don't use tau/is_match to accept.
- Within-dendrite, within-gate only. Hard negatives were trained
  within-dendrite; cross-dendrite behavior is untested. Never let a high
  score_app cross a dendrite or rescue a geometry/link rejection.
- Acceptance gate = a turnover ON-vs-OFF sensitivity run. Re-run
  finalize/registry with appearance on and off on the same FOVs; count fate
  flips and direction. If it net-reduces turnover, that's a flag to show the
  neuroscientists, not a win.
- Log score_app + checkpoint hash + crop params per decision in
  lineage_decisions.json -- otherwise model-assisted lineages aren't
  reproducible/publishable.
- Validation is currently leaky. evaluate.py uses random_pair_split --
  same-lineage pairs scattered across train/val inflates every metric. Use
  LOFO / lineage-holdout (fovs 1-6 make this feasible), stratify by
  session-pair and delta-size, report FALSE-MERGE vs FALSE-SPLIT rate not
  AUROC/accuracy. retrieval_at_1 as written never ranks against real in-gate
  distractors and reads NaN in the report -- replace it.
